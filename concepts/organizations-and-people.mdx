## Organizations

An organization holds a fleet: its agents, its people and its alerts. Everything belongs to one organization, and nothing is shared between them. A person can belong to several.

Organizations are created for you when you are invited; there is no open sign-up.

## Roles

Each person has one role in an organization.

| Role | What it adds |
| --- | --- |
| Owner | Everything, including making someone an admin |
| Admin | Manages agents, people, alerts and settings |
| Member | Sees the fleet. Can register an agent they run themselves, and manage alerts for agents they are assigned to |
| Viewer | Sees the fleet. Changes nothing |

Owners and admins see every agent in full.

## Stewards and operators

Beyond a role, a person can be assigned to an agent.

| Assignment | Meaning |
| --- | --- |
| Steward | Answers for what the agent does. Named on its directory entry |
| Operator | Keeps it running, and may start and end its maintenance. Named on its directory entry |
| Viewer | May see the agent's full page. Not named |

## What you can see of an agent

There are two levels.

- **Directory entry:** what the agent is, how to ask it for something, who looks after it, and whether it is up. Nothing about the machine it runs on.
- **Full:** also its health, incidents, uptime, alerts, versions, inventory and usage. For owners, admins and the people assigned to the agent.

## Agents a provider runs for you

An organization's agents can be operated by another organization: a provider that builds and runs agents for its client. BeaconClaw is told which organization that is.

For an agent the provider runs, how it is built and administered is for the provider's people: the names of its skills and the channel it is administered through. Everyone else in the client's organization, whatever their role, sees what the agent is connected to, where people work with it, its model provider, and the line "Administered by" with the provider's name. Health, incidents, uptime and usage are unaffected.

An agent the client runs itself is the client's in full.

## Restricted agents

An agent is **open** by default: every member can see its directory entry. An agent marked **restricted** is hidden from members who are not assigned to it. They do not see that it exists, in the app or through the API.

## Agents entered by hand

An agent with no CLI on its machine can be added by hand. It appears in the directory with its profile and people, marked as not monitored. It has no health, uptime or alerts until a CLI reports for it.

## Downloading your organization's data

An owner can download everything held about the organization as one JSON file: in **Settings**, under **Your data**. It holds the members, each agent with its incidents, maintenance, hourly health summaries, usage, version changes and connections, and the organization's alerts, alert rules and API key records.

Left out are secrets (agent tokens, API keys, and the addresses alert channels send to) and individual heartbeats, which are kept only for a short time. The file shows an owner nothing they could not already see in the app. It cannot be downloaded with an API key.

## Removing an agent, and deleting one for good

**Removing** an agent takes it out of every list and stops its token working. Its record is kept, so past uptime figures and alert history stay right.

**Deleting for good** erases it: the agent with its health history, incidents, alerts, versions, usage, the people assigned to it and its picture. An owner does this in **Settings**, under **Delete for good**, for an agent that has already been removed, by typing its name. It cannot be undone.

An owner can delete the whole organization the same way. That erases every agent and its history, everyone's membership, alert channels and rules, API keys and stored connections. People keep their own logins.

What is kept is one line per deletion: what kind of thing it was, when, and who did it. Nothing that was deleted is kept, not even its name. Deleting for good cannot be done with an API key.

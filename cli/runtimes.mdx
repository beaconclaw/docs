---
title: "Runtimes"
description: "OpenClaw and Hermes Agent, and what the CLI reads on each."
---

Each copy of the CLI reports on one agent runtime. It supports [OpenClaw](https://github.com/openclaw/openclaw) and [Hermes Agent](https://github.com/NousResearch/hermes-agent). `beaconclaw auth` saves which one: the one you give with `--runtime openclaw` or `--runtime hermes`, or the only one installed. A saved choice never changes by itself, so a runtime that is down is reported as down, not swapped for another.

Everything in the app works the same for both: health, incidents, uptime, alerts, the inventory, usage and [remote actions](/cli/remote-actions).

## What the CLI reads

| | OpenClaw | Hermes Agent |
| --- | --- | --- |
| Health | The gateway's `/health` and `/ready` | `gateway_state.json`, which the gateway rewrites at least once a minute |
| A gateway that says it is fine but has stopped working | Failing channels the gateway reports | The state file has not been rewritten for two minutes while the process is alive |
| Skills | `openclaw skills list` | Folders under `skills/` with a `SKILL.md` |
| Connections | Names under `channels`, `mcp.servers` and `models.providers` | Names of platforms, `mcp_servers`, `providers` and `model.provider` |
| Usage | `openclaw gateway call sessions.usage` | `state.db`, opened read-only: counts by role and source |
| Version | The running gateway's package | `code_version` in the state file |
| Restart | `openclaw gateway restart` | `hermes gateway restart`, without `--yes` |

On both, the CLI reads names and counts only. It never opens the runtime's environment file, never sees a credential's value, and never reads the text of a conversation.

## Hermes Agent

The CLI reads Hermes's home folder: `$HERMES_HOME`, or `~/.hermes`. Set another with `"hermes_home"` in the config file or `BEACONCLAW_HERMES_HOME`. In the official Docker image the home folder is `/opt/data`; run the CLI in the same container so it can see the gateway's process.

A restart counts as done only when a new gateway process appears. If Hermes refuses because a conversation or job is in progress, the result says the gateway was not restarted.

## Both on one machine

Each runtime is a separate agent in BeaconClaw, with its own token. Run one copy of the CLI for each, as two profiles:

```sh
beaconclaw auth --runtime openclaw
beaconclaw --profile hermes auth --token bc_... --runtime hermes
beaconclaw --profile hermes install
```

When both are installed and no choice is saved, `beaconclaw status` and the CLI's log say so and print these commands. Until then the copy reports on OpenClaw.
